# Safe Screenshot Publishing Guide

Screenshots can help recruiters evaluate this portfolio, but they should be published only after checking for confidentiality and security concerns.

## Suggested screenshots

1. **Storefront** — an anonymous product catalogue.
2. **Product details** — a sample item using fictional content.
3. **Cart** — test items and prices, with no customer account information.
4. **Administration** — a demonstration view using test or mock data only.
5. **Delivery tracking** — a simulated shipment with fictional identifiers.
6. **Mobile PWA** — an installable-app view without personal data.

## Checklist before publishing

- Use a dedicated test account and fictitious information.
- Remove names, phone numbers, email addresses, addresses and real order identifiers.
- Never display credentials, tokens, browser request headers or payment secrets.
- Prefer capturing clean test screens over blurring sensitive production details.
- Label simulations accurately and do not misrepresent unverified features as production-ready.
- Make no security or commercial-performance claims without supporting evidence.

If screenshots are added later, place approved images in **assets/screenshots/**.
